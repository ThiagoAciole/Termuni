# P3 Polish Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Search results are highlighted, conflicting shortcuts are detected, notifications follow a tested policy, and the app is compared against the visual references with a recorded list of deviations.

**Architecture:** Highlighting adds a match finder to `termac-vt.c` (pure, unit-tested) and a draw pass in the terminal. Conflict detection is one function in the application that reads the same `editable_shortcuts[]` table the editor already uses, so there is a single source of truth. Notification policy moves into a pure function. The visual comparison produces screenshots with the existing `TERMAC_UI_SCREENSHOTS` hook and a written review, because pixel diffs against hand-made mockups would give false precision.

**Execução em 13/11/2026:** branch `p3-polish`; evidências e limites em [PLANO_IMPLEMENTACAO.md](../../../PLANO_IMPLEMENTACAO.md) e [visual-review.md](../../checklists/visual-review.md). O finder usa a geometria real dos grafemas do motor, em vez de estimar por codepoint; o recuo é 12/8 conforme DESIGN.md; notificações passam a opt-in no schema. Foram incluídas regressões de evento atrasado, terminal removido e ocorrência atual. Commits mantêm autoria real, sem atribuir coautoria não realizada. Aprovação visual do usuário e notificação GNOME real permanecem pendentes.

**Tech Stack:** C, GTK 4, libadwaita, libghostty-vt, GLib `g_test`, Xvfb.

**Spec:** [PLANO_IMPLEMENTACAO.md](../../../PLANO_IMPLEMENTACAO.md), "Prioridades — 13/11/2026", item P3; visual references in [DESIGN.md](../../../DESIGN.md) and `assets/tema-*.png`.

## Global Constraints

- Search is the existing bar (`Ctrl+Shift+F`, `F3`, `Shift+F3`); no new shortcut is added for it.
- Shortcut defaults stay as they are in `editable_shortcuts[]` in `src/termac-application.c`; restoring defaults still works.
- Notifications stay opt-in through the existing `notifications` GSettings key; they fire only when the window or tab is not in focus.
- All user-visible strings are `_()`; `po/pt_BR.po` ends with 0 fuzzy.
- Do not claim visual correctness without looking at the screenshots; a person confirms the comparison.
- Commits end with `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>`.

## Review Focus

1. Matches on rows with wide (CJK/emoji) characters: highlight columns line up with the glyphs. [Task 1]
2. Search is case-insensitive for ASCII, and an empty or whitespace-only query highlights nothing. [Task 1]
3. Rebinding an action to an accelerator another action already owns is refused with a message naming the owner; rebinding to its own current accelerator is not a conflict. [Task 2]
4. A reserved terminal-key combination (the ones in `termac_window_shortcut_is_reserved`) assigned to two actions is caught too. [Task 2]
5. A notification for a tab that was closed before the user clicks it does not crash `app.show-session`. [Task 3]

### Task 1: Highlight search results

**Files:**
- Modify: `src/termac-vt.c`, `src/termac-vt.h`, `src/termac-terminal.c`, `src/termac-terminal.h`, `src/termac-window.c`, `tests/test-vt.c`, `tests/test-ui.c`

**Interfaces:**
- Produces:
  - `typedef struct { guint row; guint column; guint cells; } TermacVtMatch;`
  - `GArray *termac_vt_find_matches (GhosttyTerminal terminal, guint columns, guint rows, const char *needle)` — matches inside the current viewport only, element type `TermacVtMatch`, `column`/`cells` counted in terminal cells (wide glyphs count 2). Returns an empty array (never NULL) for an empty or whitespace-only needle. Caller frees with `g_array_unref`.
  - `void termac_terminal_set_highlight (TermacTerminal *self, const char *needle)` — NULL or empty clears.
  - `guint termac_terminal_get_highlight_count (TermacTerminal *self)` — matches currently visible; used by tests.

- [x] **Step 1: Write the failing tests** in `tests/test-vt.c`: feed `"foo bar Foo\r\nxfoo"` to a test terminal; `/vt/find-matches` asserts needle `"foo"` gives 3 matches, first `{row 0, column 0, cells 3}`, second `{0, 8, 3}`, third `{1, 1, 3}`; `/vt/find-matches-wide` feeds `"日本語 foo"` and asserts the `foo` match has `column == 7` (three wide glyphs = 6 cells plus a space); `/vt/find-matches-empty` asserts `len == 0` for `""` and `"  "`.
- [x] **Step 2: Run** `meson test -C build vt`. Expected: FAIL (function missing).
- [x] **Step 3: Implement** `termac_vt_find_matches` on top of `termac_vt_viewport_row_text`, mapping byte offsets in the row text to cell columns by walking UTF-8 characters and using `g_unichar_iswide`. In `termac-terminal.c` store the needle, recompute matches before drawing a frame, and draw a translucent rectangle (theme accent at about 35% alpha) over each match cell range, with the selected/current match drawn stronger. `find_entry_search_changed_cb` and `find_entry_activate_cb` call `termac_terminal_set_highlight`; closing the bar (`notify::search-mode-enabled` false) clears it.
- [x] **Step 4: Write the UI test** `/ui/search-highlight`: run `echo marker marker`, open the bar via `win.find`, type `marker` in the entry, assert `termac_terminal_get_highlight_count ()` is at least 2; close the bar and assert 0. Save `search-highlight.png` with `save_widget_png` for the visual review.
- [x] **Step 5: Run** `meson test -C build`. Expected: all OK. Commit `feat: highlight search matches in the terminal`.

### Task 2: Shortcut conflict detection

**Files:**
- Modify: `src/termac-application.c`, `tests/test-ui.c`, `po/pt_BR.po`

**Interfaces:**
- Produces: `static const char *shortcut_find_conflict (TermacApplication *self, const char *action, const char *accel)` — returns the action name that already uses an equivalent accelerator, or NULL. Equivalence is by `gtk_accelerator_parse` key and modifiers (so `<Shift><Control>t` equals `<control><shift>t`); the effective accelerator of each action is its override or its default. The action being edited is skipped.

- [x] **Step 1: Write the failing tests** in `tests/test-ui.c`, modelled on `test_terminal_shortcut_rebind`: `/ui/shortcut-conflict`: try to assign `<control><shift>w` (owned by `win.close-tab`) to `win.new-tab` through the editor's apply path; assert the setting `action-shortcuts` is unchanged, `win.new-tab` still has `<control><shift>t`, and the message shown names the owning action's title ("Close tab"). Also assert assigning `win.new-tab` its own current accelerator is accepted (Review Focus 3), and that the equivalent spelling `<Shift><Control>w` conflicts too.
- [x] **Step 2: Run** `... -p /ui/shortcut-conflict`. Expected: FAIL (no detection).
- [x] **Step 3: Implement** `shortcut_find_conflict` and call it where the editor commits a new accelerator (the code that calls `shortcut_override_set`); on conflict do not write the setting and show the existing in-dialog feedback (reuse the row's subtitle or a toast) with a translated string such as `"%s is already used by %s"`. Remove the hard-coded duplicate `gtk_application_set_accels_for_action` calls near the top of the registration block so only `termac_application_apply_action_shortcuts` sets accelerators.
- [x] **Step 4: Run** `meson test -C build`. Expected: all OK including `/ui/shortcut-editor` and `/ui/terminal-shortcut-rebind`. Translate the new string, 0 fuzzy.
- [x] **Step 5: Commit** `feat: refuse conflicting shortcuts and name the owner`.
